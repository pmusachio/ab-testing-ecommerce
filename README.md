# AB Testing Ecommerce

Data science portfolio project built on the Kaggle [A/B Testing](https://www.kaggle.com/datasets/zhangluyuan/ab-testing) dataset. It walks through a full applied-statistics workflow — from business framing to a reproducible analysis pipeline and a deployable prediction API — following the project structure and best practices described in *Hands-On Machine Learning with Scikit-Learn and PyTorch* (Aurélien Géron).

## TL;DR for Recruiters

Want to see it run without setting up Python locally? Use Docker:

```bash
git clone <YOUR_REPOSITORY_URL> ab-testing-ecommerce
cd ab-testing-ecommerce
docker compose up --build
```

Then check the API is alive:

```bash
curl http://localhost:8000/health
# {"status": "ok"}
```

That single command builds the image, installs all dependencies, and serves the prediction API on `http://localhost:8000`. See [Quickstart](#quickstart) below for the local (non-Docker) path and for running the analysis/notebooks.

## 1. Business Problem

An ecommerce company needs to decide whether a new checkout/landing page experience increases conversion in a statistically reliable way.

**Goal:** Measure whether the new experience changes conversion in a statistically consistent manner.

**Key metrics:** absolute lift, relative lift, two-proportion z-test and p-value.

## 2. Business Assumptions

- The decision must weigh statistical significance together with effect size.
- Users must be correctly split between control and treatment groups.
- Even a small lift can matter if the user base or revenue is large.

## 3. Solution Strategy

1. **Step 01. Data Description:** validate schema, dimensions, nulls, types and granularity.
2. **Step 02. Feature Engineering:** create domain-oriented variables.
3. **Step 03. Data Filtering:** remove records with no analytical value or leakage risk.
4. **Step 04. Exploratory Data Analysis:** validate hypotheses and separate signal from noise.
5. **Step 05. Data Preparation:** impute, scale and encode variables for modeling.
6. **Step 06. Feature Selection:** separate IDs, target, input variables and dropped columns.
7. **Step 07. Machine Learning Modeling:** train a reproducible baseline and evaluate technical metrics.
8. **Step 08. Hyperparameter/Fit Strategy:** reserve room for tuning, threshold choice and model comparison.
9. **Step 09. Business Translation:** convert metrics into a decision, prioritization, risk, revenue or operational read.
10. **Step 10. Delivery:** produce the statistical report, business reading and executive recommendation for the experiment.

## 4. Data Source

Kaggle source: [A/B Testing](https://www.kaggle.com/datasets/zhangluyuan/ab-testing).

Expected files:

- `data/raw/ab_data.csv`

The main flow uses `ab_data.csv`, which contains the experiment group, landing page and conversion flag.

## 6. Top Data Insights and Hypotheses

- The new page increases the conversion rate.
- The observed difference can be explained by sampling variation.
- The sample size is large enough for an initial decision read.

## 7. Model or Analysis Applied

Two-proportion z-test computing conversion rate, absolute lift, relative lift and p-value.

## 8. Performance and Business Results

Result reproduced in `reports/ab_test_results.json`: control = 12.04%, treatment = 11.89%, relative lift = -1.23%, p-value = 0.2161. Since the p-value is above 0.05, the business reading is to **not** roll out the new experience automatically without further evidence.

Main pipeline outputs:

- `reports/ab_test_results.json`

## 9. Business Translation

The result avoids adopting a new experience without statistical evidence of a real gain, protecting the business from a costly false positive.

## 10. Repository Structure

- `configs/project.toml`: project contract — data, target, metrics and parameters.
- `src/ab_testing_ecommerce/`: modular Python package for data, features, modeling, analysis and serving.
- `notebooks/`: the analytical journey as notebooks.
- `data/raw/`: files downloaded from Kaggle or the prepared analytical base.
- `reports/`: metrics, profiles and results generated by the pipeline.
- `models/`: trained model artifact, when applicable.
- `Dockerfile` / `docker-compose.yml`: container definitions to build and serve the prediction API.
- `.github/workflows/ci.yml`: continuous integration — runs the test suite and builds the Docker image on every push/PR.

## Quickstart

### Option A — Docker (recommended, no local Python setup)

Requires only [Docker](https://docs.docker.com/get-docker/).

```bash
git clone <YOUR_REPOSITORY_URL> ab-testing-ecommerce
cd ab-testing-ecommerce
docker compose up --build
```

The API becomes available at `http://localhost:8000` (interactive docs at `http://localhost:8000/docs`). Stop it with `docker compose down` (or `make docker-down`).

> Note: the `/predict` endpoint requires a trained model artifact at `models/model.joblib`. Run `make train` locally first (see Option B) to generate it, or mount your own artifact into `models/`.

### Option B — Local Python environment

```bash
git clone <YOUR_REPOSITORY_URL> ab-testing-ecommerce
cd ab-testing-ecommerce
python -m venv .venv
source .venv/bin/activate
make install
```

Run the workflow:

```bash
make profile   # writes reports/data_profile.json
make analyze   # runs the AB-test analysis -> reports/ab_test_results.json
make train     # trains the baseline model -> models/model.joblib
make api       # serves the FastAPI app locally with auto-reload
make test      # runs the test suite
```

Or call the CLI directly:

```bash
PYTHONPATH=src python -m ab_testing_ecommerce.cli validate-config
PYTHONPATH=src python -m ab_testing_ecommerce.cli profile
PYTHONPATH=src python -m ab_testing_ecommerce.cli analyze
```

### Running the notebooks

```bash
make install
PYTHONPATH=src jupyter lab
```

Open the notebooks in `notebooks/` in the suggested order (see [notebooks/README.md](notebooks/README.md)).

### Getting the dataset

The dataset is not bundled in the repository. Download it via the Kaggle API:

```bash
mkdir -p data/raw
pip install kaggle
kaggle datasets download -d zhangluyuan/ab-testing --unzip -p data/raw
```

See [data/raw/README.md](data/raw/README.md) for details.
